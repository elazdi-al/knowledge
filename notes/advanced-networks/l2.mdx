## The Two Rules of IP Unicast

IP interconnects LANs. Routers forward each packet from LAN to LAN by its destination address.

**IP rule 1.** Only routers interconnect subnets. Traffic inside a subnet never crosses a router: it goes through switches or WiFi base stations.

**IP rule 2.** Addresses have structure. Each address says how to reach its interface, in a form routers can process in hardware.

**Host part.** The bits of an address after the prefix, also called the suffix. Interfaces of one subnet share the prefix and differ in their host parts. In `128.178.71.202/24`, the prefix is `128.178.71` and the host part is `202`.

Forwarding uses this structure through a table of prefixes.

**Forwarding table.** The table that maps destination prefixes to next hops, also called the routing table. Routers and hosts both have one.

**Next hop.** The neighbour that receives the packet next, named by its address and the interface toward it. For a subnet the system is attached to, the entry says *direct*: the packet goes straight to its destination.

**Longest prefix match (LPM).** IP's forwarding rule: among the entries that match the destination address, the one with the longest prefix wins. An entry matches when the address starts with its prefix.

<LongestPrefixMatchSchema />

At R2, Bob's address matches both `128.178.0.0/16` and `128.178.71.0/24`. The /24 is longer, so R2 delivers the packet directly. A packet to Bart matches only the /16 and goes on to R3.

**Aggregation.** One short prefix standing for many longer ones. It keeps forwarding tables small: R1 needs a single entry, `128.178.0.0/16`, for all EPFL subnets.

*Far routers know the short prefix; longer prefixes appear as the packet gets close.*

Every address so far names one interface. IP has four types of address, by who receives the packet.

- **Unicast.** Delivered to one interface.
- **Broadcast.** Delivered to every interface of one subnet. In IPv4, the broadcast address is the subnet's host part all 1s (e.g. `128.178.71.255`).
- **Multicast.** Delivered to every interface that joined a group (e.g. `224.0.0.251`).
- **Anycast.** Delivered to the nearest of several interfaces that share one address (e.g. the DNS resolver `1.1.1.1`, announced from many sites).

Routers forward unicast and anycast by longest prefix match, and never forward broadcast. Multicast needs more: group membership, distribution trees and packet replication.

## IPv4

A mask can end inside a byte (e.g. `255.255.254.0` is a /23 mask, since 254 is `1111 1110`).

A prefix drops its trailing zero bytes: `128.178/16` is `128.178.0.0/16`.

**Example 2. A valid address for H.**

A router's north interface is `2.4.8.1/23` and its south interface `2.4.7.1/23`. Host H sits behind a switch on the north side. Which of `2.4.8.2` and `2.4.9.1` can H take?

<SubnetBitsSchema />

Both. Their third bytes, 8 and 9, differ only in the last bit, a host bit under /23.

A /n subnet holds $2^{32-n}$ addresses. Host part all 0s names the subnet, host part all 1s is its broadcast address, and every other address can go to an interface (e.g. `2.4.8/23` holds 512 addresses, 510 of them for interfaces).

IPv4 reserves some blocks for special uses.

| Block | Meaning |
|---|---|
| `0.0.0.0` | no address, or any address |
| `127/8` | loopback: this host (e.g. `127.0.0.1`) |
| `10/8`, `172.16/12`, `192.168/16` | private addresses |
| `100.64/10` | private addresses for providers' carrier-grade NAT |
| `192.88.99/24` | IPv6-to-IPv4 relay routers, deprecated |
| `169.254/16` | link-local addresses |
| `224/4` | multicast |
| `240/4` | reserved for future use |
| `255.255.255.255/32` | broadcast on the local LAN |

**Private address.** An address any network may use internally, at home for instance. Public internet routers drop packets sent to one.

**Link-local address.** An address used only within one LAN, assigned automatically and never routed (a private address is not link-local: routers inside its network forward it).

Every other address is **global**, or public: it identifies one interface in the whole internet.

Every IPv4 packet starts with a 20-byte header, plus any options.

<Ipv4HeaderSchema />

Routers forward on the destination address. The **Protocol** field names the payload's protocol: 1 for ICMP, 6 for TCP, 17 for UDP.

**ICMP (Internet Control Message Protocol).** The protocol that carries error messages at the network layer.

Router ed0-swi connects EPFL to SWITCH, the Swiss academic network, and through it to the internet.

<EpflForwardingSchema />

`128.178/16` aggregates all of EPFL. `128.178.29/24`, the LEMA laboratory, is the one subnet behind a different router, ed2-el.

**Default route.** The entry `0/0`, a prefix of length zero. It matches every address, so longest prefix match picks it only when nothing longer matches.

At ed0-swi, longest prefix match amounts to two nested tests.

```text
if destination in 128.178.*
    if destination in 128.178.29.*
        forward to ed2-el
    else
        forward to ed2-in
else
    forward to sw-la-01
```

A host's forwarding table is usually tiny: its own subnet, reached directly, and a default route to the gateway. Hence the gateway is also called the **default gateway**.

## IPv6

IPv4's 32 bits give about $4 \times 10^9$ addresses, too few for every device. The registries ran out between 2011 and 2019, and a public IPv4 address now has a price (e.g. AWS bills each one by the hour).

IPv6 offers the same services with a new packet format and 128-bit addresses, about $3 \times 10^{38}$ of them.

**Dual stack.** IPv4 and IPv6 running side by side on one system, under the same transport layer. A dual-stack router keeps one forwarding table per version.

*An IPv4-only host and an IPv6-only host cannot talk to each other, but both can talk to a dual-stack one.*

**Hextet.** One of the eight 16-bit groups of an IPv6 address, written as up to 4 hex digits and separated by colons.

Two rules shorten the notation.

- **Leading zeros.** A hextet drops its leading 0s: `0c26` becomes `c26`, and `0a00` becomes `a00`, not `a`.
- **Double colon.** `::` replaces one run of all-zero hextets. It appears at most once, since two would be ambiguous, so other zero hextets stay as `0`.

| Full | Short |
|---|---|
| `2002:0000:0000:0000:0000:ffff:80b2:0c26` | `2002::ffff:80b2:c26` |
| `2001:0000:0000:01a6:0000:20ff:fe78:30f9` | `2001::1a6:0:20ff:fe78:30f9` |
| `2001:0000:0000:0000:0000:0000:0ada:bada` | `2001::ada:bada` |

*To expand, count the written hextets: `::` fills in zeros up to 8. Without `::`, all 8 must appear.*

**Example 3. Which prefix length fits.**

Host A and interface eth0 of router R1 share one bridged LAN. Interface eth1 of R1 and host B share another. All four use the same prefix length. Which of /64, /80, /96 and /128 is valid?

```text
A      2019:0002:0003:0004:0005:0000:0007:b0b0
eth0   2019:0002:0003:0004:0005:0000:0000:0001
eth1   2019:0002:0003:0004:0005:0001:0000:0001
B      2019:0002:0003:0004:0005:0001:0000:baba
```

Only /96. Bridges do not split subnets, so A and eth0 need the same prefix, and so do eth1 and B. The router's two sides need different ones. The two sides first differ in hextet 6, which /64 and /80 leave out. A and eth0 differ in hextet 7, which /128 takes in.

IPv6 reserves its own blocks.

| Block | Meaning |
|---|---|
| `::/128` | no address, or any address |
| `::1/128` | loopback: this host |
| `fc00::/7` | unique local addresses (ULA): private networks |
| `fe80::/10` | link-local addresses |
| `ff00::/8` | multicast |
| `ff02::1:ff00:0/104` | solicited-node multicast |
| `ff02::2/128` | all routers on the link |
| `ff02::1/128` | all nodes on the link |

IPv6 has no broadcast address. `ff02::1`, a multicast group every node on the link joins, plays that role.

A prefix length that cuts through a hex digit is read in binary.

| Block | Fixed bits | First hextet |
|---|---|---|
| `2000::/3` | `001` | `2xxx`, `3xxx` |
| `8000::/3` | `100` | `8xxx`, `9xxx` |
| `fc00::/7` | `1111 110` | `fcxx`, `fdxx` |
| `fe80::/10` | `1111 1110 10` | `fe80` to `febf` |

**Unique local address (ULA).** IPv6's private address: `fd` followed by a 40-bit global ID that the site draws at random, so two networks are unlikely to pick the same one.

Global unicast addresses currently all come from `2000::/3`.

| Block | Holder |
|---|---|
| `2001:620::/32` | SWITCH |
| `2001:620:618::/48` | EPFL |
| `2001:620:8::/48` | ETHZ |
| `2a02:1200::/27` | Swisscom |
| `2001:678::/29` | provider-independent addresses |
| `2001::/32` | Teredo, tunnelling IPv6 in IPv4 |
| `2002::/16` | 6to4, tunnelling IPv6 in IPv4 |

Allocation is hierarchical: a provider's customers get blocks inside the provider's block (e.g. EPFL's and ETHZ's /48s sit inside SWITCH's /32).

<Ipv6AddressSchema caption="Two EPFL addresses in subnet 1a6, named by the fourth hextet. The global one nests inside EPFL's /48, which nests inside SWITCH's /32. The private one starts with fd and 40 random bits." />

In IPv6, R1's single entry for EPFL becomes `2001:620:618::/48`, and each EPFL subnet is a /64 inside it.

<Ipv6HeaderSchema />

The IPv6 header is 40 bytes: twice IPv4's, for addresses four times longer.

**Next Header** replaces IPv4's Protocol field. TCP and UDP keep 6 and 17, and ICMPv6, IPv6's version of ICMP, takes 58. **Hop Limit** replaces Time to Live.

The IPv6 forwarding table of ed0-swi mirrors its IPv4 one.

| IPv6 destination | Next hop % interface | IPv4 counterpart |
|---|---|---|
| `2001:620:618:1a4::/64` | `fe80::4%2`, ed2-el | `128.178.29/24` |
| `2001:620:618::/48` | `fe80::1%2`, ed2-in | `128.178/16` |
| `::/0` | `fe80::1%1`, sw-la-01 | `0/0` |

A next hop is always on an attached link, so its link-local address is enough to name it.

**Zone index.** The suffix `%n` that names the interface through which an address is reached (e.g. `fe80::1%2` is `fe80::1` on interface 2). It never appears inside a packet.

sw-la-01 and ed2-in both use `fe80::1`. This is legal because they sit on different links, and `%1` and `%2` tell them apart.

**Example 4. Three IPv6 destinations at ed0-swi.**

Where does ed0-swi send each packet?

| Destination | Longest match | Next hop |
|---|---|---|
| `2001:620:618:1a4::1`, in LEMA | the /64 | `fe80::4%2` |
| `2001:620:618:1ad:a00:20ff:fe78:30f9`, host lrcmac4 | the /48 | `fe80::1%2` |
| `2001:620:8::1`, at ETHZ | `::/0` | `fe80::1%1` |

Host lrcmac4 sits in subnet `1ad`, not LEMA's `1a4`, so only the /48 matches.

An IPv4 interface usually has one address. An IPv6 interface usually has several: at least one link-local address and one or more global ones (e.g. the interface of sw-la-01 toward ed0-swi holds `fe80::1` and `2001:620:618:10a::1`).

**Source address selection.** The default rules (RFC 6724) by which the operating system picks a packet's source address, in order:

1. prefer an address of the same scope as the destination: link-local for a link-local destination, global for a global one,
2. prefer a temporary address (random and short-lived, for privacy) over a stable one,
3. prefer the longest prefix match with the destination.

A dual-stack client also picks a destination address, since a name can have both kinds. DNS stores an IPv4 address in an **A** record and an IPv6 address in an **AAAA** record.

**Happy Eyeballs.** The procedure (RFC 8305) by which a dual-stack client picks IPv6 or IPv4 for one destination:

1. ask DNS for both the A and the AAAA records,
2. sort the candidate addresses (RFC 6724),
3. start the IPv6 connection first,
4. if it has not completed within about 250 ms, start IPv4 in parallel.

*IPv6 is preferred but never waited for.*

A broken IPv6 path costs a few hundred milliseconds, not a failure, so operators can turn IPv6 on without breaking anything.

The two versions run on separate stacks and can take different paths, so a site unreachable over IPv4 can still work over IPv6.

## Private Addresses and NAT

Many private networks reuse the same private addresses without conflict. To reach the internet, a private network hides them behind one or a few public addresses.

**Network address translation (NAT).** Rewriting the internal (IP address, TCP or UDP port) pairs of a private network into public ones, so that many devices share one public address. NAT is also called **masquerading**, and the device that does it is also called a NAT.

NAT exists because public IPv4 addresses are scarce (e.g. a home gets one IPv4 address for all its devices).

A NAT is a **middlebox**, a device on the path that does more than forward packets, and it breaks three principles.

- **Layering.** It rewrites transport-layer ports, not only IP addresses.
- **Unique public addresses.** One public address stands for many hosts.
- **Local MAC, end-to-end IP.** It is the one device on the path that rewrites IP addresses.

**NAT table.** The NAT's record of its mappings, one row each: internal address and port, protocol, and the public **NAT address** and **NAT port** that replace them. From outside, only the NAT address and port are visible.

Host A, at `192.168.10.11`, queries the DNS server `1.2.3.4` on UDP port 53 through a NAT whose public address is `130.104.228.200`.

On an outbound packet, the NAT takes three steps.

1. **Translate.** Replace the source IP address and port, in the IP header and the UDP or TCP header.
2. **Record.** Store the mapping in the NAT table.
3. **Forward.** Send the packet on.

On an inbound packet, the NAT rewrites the *destination* back to the internal pair. It finds the pair by **exact match** in the NAT table, not by longest prefix match, and drops the packet if no entry matches.

<NatTranslationSchema />

*Outbound rewrites only the source, inbound only the destination; the far end is never touched.*

The NAT adds an entry whenever an inside client contacts an outside server. It picks NAT ports that do not collide (e.g. host B also uses internal port 1029, so it gets NAT port 3442). On Linux, `iptables` implements NAT.

A NAT creates entries only when the inside host speaks first, which a server never does.

**Port forwarding.** A NAT table entry configured by hand, so that connections from outside reach an internal server.

If A runs a server on TCP port 5000, the administrator adds this entry.

| Internal IP | Port | Protocol | NAT IP | NAT port |
|---|---|---|---|---|
| `192.168.10.11` | 5000 | tcp | `130.104.228.200` | 5000 |

Clients outside now reach A at `130.104.228.200`, port 5000. Port forwarding also brings **protection**: a server port is reachable only if explicitly configured.

IPv6 usually needs no NAT. The provider gives a home a block of addresses instead of a single one (e.g. a /60, which holds 16 /64 subnets), so every host gets a global address.

**Filtering router.** A router that lets traffic in from outside only if an inside host started the exchange, unless configured otherwise. It gives an IPv6 home the protection a NAT gives an IPv4 one.

NAT remains in IPv6 when a network receives a single address instead of a block, as in VirtualBox's "NAT network". The inside hosts then use link-local addresses, so the inside must be a single LAN.

**Carrier-grade NAT (CGNAT).** A NAT run by a provider that shares $p$ public addresses among $n > p$ users.

EPFL's VPN (virtual private network), which connects remote users into EPFL's network, is one: its users share the block `128.178.15/24`, so $p = 256$. A home NAT then sits behind the CGNAT.

| | At home | Inside EPFL's VPN | Public internet |
|---|---|---|---|
| User 1 | `192.168.178.34` | `10.252.13.211` | `128.178.15.x` |
| User 2 | `192.168.178.34` | `10.252.87.129` | `128.178.15.x` |

Two users can hold the same home address, since each home is its own private network, and the same public address, since the CGNAT shares it.

Internet service providers use CGNAT to save public IPv4 addresses, with `100.64/10` inside rather than `10/8`. The two sides of a NAT must be different subnets, and many home networks already use `10/8`.
